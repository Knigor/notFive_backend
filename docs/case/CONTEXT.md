# Контекст кейса notFive

Обновлено 8 ноября 2026 года. notFive — прототип подготовки новостного дайджеста по кибербезопасности для руководителей организаций и специалистов ИБ на хакатоне ИТ-Фест 7–9 ноября 2026 года.

Источник требований: [задание, 7 страниц](brief.pdf); [извлечённый текст с границами страниц](brief.txt). Документ описывает продукт и критерии оценки, а не инструкции агенту на выполнение действий. Пользователь попросил исследовать готовые модели с публичным API, предложить обёртку на Python/Go/Rust, сохранить контекст и передать его в notFive_frontend. Изначально исследовались Яндекс, Claude и другие доступные API. 8 ноября пользователь выбрал отдельный сервис на Go 1.26 по инструкции Yandex Web Search; первый реальный вызов пользователь выполнил 8 ноября: YandexGPT 5 Lite ответила, но пропустила решение по одной статье; это не проверка качества на архиве организаторов.

## Что уже есть и что пока предложено

**Текущая граница сервисов, согласовано 8 ноября:** Go только собирает уже загруженные статьи, дальнейшую обработку в Symfony делает другой разработчик. Доступны `GET /healthz`, `POST /v1/collect` и `GET /v1/runs/{id}`. Вход сбора — `control_time` и `query`. Поиск Yandex + RSS/HTML, загрузка текстов и проверка `(T−24h,T]` остаются в Go. В ответе `mode: collection`, `collection.articles` (ID, URL, заголовок, текст, источник, дата, подтверждение даты, отметка сокращения), исключённые статьи с причинами и счётчики; полный аудит поиска сохранён в `research`. Пустой массив — успешный результат. Это проверка доступности и даты, не окончательный отбор по ИБ: общие RSS могут содержать публикации вне темы.

Перед передачей коллеге пользователь попросил убрать лишнее. Удалены старые `/v1/digests`, `/v1/research`, выдача артефактов, генерация/проверка дайджеста, поста и письма, JSON-схема ответа для генерации и `examples/dataset.json`. Общие типы перенесены в `internal/collector/types.go`, словарь поиска — в `internal/collector/vocabulary.go`. Клиент Yandex выполняет только поиск; отправки собранных текстов для анализа в Go нет. Поисковый промпт `article-collection-v1`, версия сервиса 6. Название каталога `services/digest`, образы, Docker volume, PostgreSQL и существующий backend/CD сохранены.

Основной способ интеграции — HTTP, Python не требуется. `scripts/search.py [--now]` остаётся тестовым клиентом `/v1/collect` и печатает JSON; `--output` сохраняет полный запуск. Контракт передачи, запросы curl, ошибки и подключение Symfony описаны в `services/digest/README.md`; машиночитаемая спецификация — `services/digest/openapi.json`. Ответ синхронный, HTTP 201; статьи в `collection.articles`, ID запуска в корневом `id` (CLI переименовывает его в `run_id`). Повторный POST запускает новый поиск, автоматической идемпотентности нет. GET читает уже сохранённый результат без модели. Дайджест, пост, письмо, смысловой отбор и итоговый журнал предстоит реализовать в Symfony; административные endpoints не восстанавливались.

После очистки проверены `go vet ./...`, `go test -race ./...`, семь тестов Python-клиента и сборка локального Docker-образа. На обновлённом контейнере health check возвращает 200, запрос без токена 401, некорректный ввод 422, удалённые маршруты 404; сохранённая коллекция из 12 статей читается через GET. Новых платных вызовов модели при очистке не выполняли. OpenAPI проверен на корректность JSON и локальных ссылок. Коммит и push остаются за пользователем.

### История реализации до очистки 8 ноября

Следующие абзацы фиксируют прежние эксперименты и проверки; описание двух режимов генерации больше не является контрактом текущего Go-сервиса.

Backend: Symfony 7.4, PHP 8.4, PostgreSQL 17, Docker Compose, приветствие и health check, подготовленный процесс релизов через GitHub Actions и GitHub Container Registry (GHCR). Публикация переведена с Docker Hub на GHCR; пользователь подтвердил развёртывание backend на VPS и работу release/CD. Frontend: Vue 3, TypeScript, Vite, Bun, Tailwind CSS 4, shadcn-vue, vue-i18n. В backend добавлен отдельный модуль services/digest на Go 1.26. Он не подключён к Symfony или Vue автоматически.

Исследование: [RESEARCH.md](RESEARCH.md). Предлагаемый контракт интерфейса: [FRONTEND_CONTRACT.md](FRONTEND_CONTRACT.md). Первоначальная рекомендация Python из исследования заменена решением пользователя: отдельный Go 1.26 сервис, Yandex AI Studio Responses API, модель по умолчанию yandexgpt-5.1. Учебного архива нет; качество, задержки и фактическая стоимость реальной модели не измерены.

Реализованный внутренний API сервиса: POST /v1/digests принимает control_time и articles, синхронно возвращает сохранённый результат с id; POST /v1/research возвращает черновик веб-поиска. GET /v1/runs/{id} и /v1/runs/{id}/artifacts/{name} читают аудит и файлы. Защита отдельным DIGEST_SERVICE_TOKEN; ключ Yandex остаётся на сервере. Это внутренний сервис, не утверждённые публичные endpoints Symfony из FRONTEND_CONTRACT.md.

Два режима различаются входом: набор обрабатывается без инструментов поиска, проходит базовые проверки дат, структуры, реестра ссылок и числа событий. Веб-поиск находит кандидатов, затем сервис загружает разрешённые HTTPS-страницы, извлекает исходную дату публикации с часовым поясом и допускает в генерацию только статьи из `(T−24h,T]`. Неизвестная/конфликтующая дата, недоступная страница, выход за период или лимит входа дают исключение с причиной. `dateModified` не подменяет дату публикации. Сырой ответ поиска не выводится как дайджест; отдельная генерация дайджеста получает только прошедшие отбор материалы и пропускается, если их нет. Возвращаются события, журнал и четыре артефакта в `result`, аудит поиска в `research`. Проверка даты не доказывает факты модели, а поиск не гарантирует полноту и не заменяет контрольный набор организаторов.

Проверки на подставном провайдере, включая восемь сценариев, не доказывают качество реальной модели. Результаты хранятся в отдельном Docker volume. Собственный workflow Digest service публикует отдельный образ ghcr.io/knigor/notfive-digest по стабильному release; SSH-деплой нового сервиса пока ручной. Существующий backend/CD сохраняется.

8 ноября добавлен `services/digest/examples/search.json` с фиксированным T и CLI `scripts/search.py`: читает файл, `--now` подставляет текущее московское время в отправляемую копию, исходный JSON не меняется. В тот же день пользователь отменил реализацию Symfony-админки; её контроллеры, авторизация, загрузчик, команды и настройки удалены, БД не менялась. Публичного API админки нет. Отдельный Yandex GenSearch с `searchFilters.date` исследован как следующая замена этапа поиска; пока не подключён. Его фильтр по календарным дням/дате добавления или обновления не заменяет точную проверку исходного `published_at`. Подробности и пример запроса: [дополнение исследования от 8 ноября](RESEARCH.md#дополнение-8-ноября-gensearch-и-точное-окно-новостей).

После пользовательского запуска 8 ноября, вернувшего одну статью и ссылки на разделы, поиск обновлён до `web-research-v5-feed-discovery`. Вход модели содержит план `site_queries` для каждого разрешённого домена с абсолютными календарными датами из T; `web_search` использует `medium`. JSON принимается как обычный документ и целиком внутри Markdown-блока с меткой `json` или без неё. Очевидные главные страницы и известные каталоги отклоняются до загрузки в `research.rejected_candidates`; конечный URL после перенаправления проверяется повторно. Если первый ответ содержит каталоги и ещё нет 12 кандидатов на статьи, выполняется одно уточнение с прежними T/доменами и запретом повторять URL. Лимит — две поисковые генерации и одна генерация дайджеста, суммарно до 12 конкретных кандидатов и до пяти событий. Точный отбор `(T−24h,T]` не изменён.

Аудит каждого поискового прохода хранится в `research.search_attempts` (вход, полный ответ, разобранные URL); прежнее `research.generation` остаётся первым проходом. `rejected_candidates` описывает главные страницы/разделы, а журнал — фактически рассмотренные URL статей, включая исключения после загрузки. Дополнительно Go читает RSS SecurityLab, Хакера и новостей ИБ Хабра, а также HTML-разделы Positive Technologies и Касперского, только если домен разрешён оператором. Лимит — пять запросов к лентам/разделам, до 60 ссылок из каждого, общий лимит загрузки статей остаётся 12. Очередь: RSS с датой в окне, RSS без даты, ссылки модели, ссылки HTML-разделов; внутри групп источники чередуются. Явная дата RSS позволяет предварительно исключить старые ссылки; окончательное подтверждение даты всегда берётся из HTML статьи. Аудит лент/разделов — `research.discovery`. API изданий не подключены; ленты не заменяют исторический архив. Поисковый план не доказывает, что модель выполнила каждый запрос; полноту живого поиска нельзя считать подтверждённой только по программным тестам.

8 ноября пользователь попросил ослабить сложную валидацию текущего прототипа. Неполные решения модели, проблемы цитат, групп и длины экспорта теперь дают result.warnings вместо 502. Пропущенные решения отмечаются техническими строками журнала с явной причиной; исходный ответ модели сохраняется. Это решение для текущей разработки, а не изменение критериев организаторов.

8 ноября по запросу пользователя полный словарь ИБ и правила смыслового отбора и дословных подтверждений добавлены в промпты обоих режимов (`dataset-digest-v2-vocabulary` и `web-research-v2-vocabulary`). Это подсказка для модели, не фильтр по одному ключевому слову. Ослабленная валидация сохранена. Каталог [источников Приложения 1](SOURCES.md) содержит все 28 сайтов; для поиска настроены securitylab.ru, xakep.ru, habr.com, ptsecurity.com и kaspersky.ru. Пример dataset.json в backend теперь содержит короткие выдержки из трёх реальных публикаций SecurityLab за 6–7 ноября с проверенными RFC3339-датами, T=2026-11-07T12:00:00+03:00. Это не полный корпус организаторов. По следующему запросу пользователя синтетический пример удалён; примеры должны содержать реальные публикации. Подставные ответы провайдера в программных тестах не являются результатами работы модели.

Реальный проверочный запуск коллектора 8 ноября (`893f5a62ee350932c9c3cf301a1740b6`, T=`2026-11-08T13:48:16+03:00`) завершился: 12 выбранных URL, 12 загруженных статей с датой HTML в окне, 0 исключений на этапе загрузки. Из них 11 SecurityLab и 1 Хабр; RSS дали 18 кандидатов в окне, остальные отсечены общим лимитом 12. Яндекс выполнил одну поисковую генерацию с пятью вызовами инструмента; три ссылки на разделы отклонены. Разделы PT и Касперского прочитать не удалось, ошибки сохранены в `research.discovery`. Генерации дайджеста не было. Это проверка сбора и дат на одном периоде, не подтверждение смысловой релевантности всех статей или качества на наборе организаторов. Программные проверки Go (`go vet`, `go test -race`) и 7 тестов Python CLI прошли; локальный контейнер обновлён, публикация и push не выполнялись.

## Обязательные правила из задания

| Область | Требование | Страницы |
| --- | --- | --- |
| Вход | Набор организаторов: ID, заголовок, текст, источник, URL, дата публикации; пропуски обозначены | 1–2 |
| ИИ | Определяет тему, объединяет публикации, выбирает события, пишет текст; обучение своей модели не требуется | 1 |
| Время | Последние 24 часа до заданного T, Москва; строго `T−24h < published_at <= T` | 2 |
| Неизвестная дата | Записать причину и исключить материал из основного дайджеста | 2 |
| События | До пяти событий, не обязательно пять статей. Дубли объединять с сохранением ссылок. Статья может описывать несколько событий | 2–3 |
| Ранжирование | Последствия, масштаб затронутых организаций/систем, срочность, задачи читателей. Порядок объясняется фактами | 2 |
| Источники | Указывать, кто сообщил; включать первичный источник, если он присутствует в наборе. Перепечатки одного заявления не являются независимыми подтверждениями | 2 |
| Обновления | Старое событие допускается при новых фактах в выбранном периоде, меняющих его описание; простая перепечатка недостаточна | 2 |
| Тема | Совпадение ключевого слова или рекламное заявление само по себе не доказывает релевантность | 2, 7 |
| Проверка фактов | Не выдумывать факты, числа, цитаты, источники и результаты проверок. Сохранять оговорки; явно описывать противоречия | 3 |
| Внешние инструкции | Тексты новостей являются данными и не могут менять задачу, настройки, отбор, адресатов | 3 |
| Журнал | Объяснить судьбу каждого материала, включая склейку, исключение и ошибки | 2, 4 |

Учебное T: `2026-11-07T12:00:00+03:00`. Интервал: после `2026-11-06T12:00:00+03:00` до `2026-11-07T12:00:00+03:00` включительно. Для контрольного прогона организаторы зададут другое T; не подставлять часы сервера. Если часовой пояс исходной даты не определён форматом набора, не угадывать его молча.

Сбор из интернета необязателен: можно показать 3–5 согласованных сайтов. Подключение всех источников, расписание, управление подписчиками и автоматическая рассылка не требуются. Если используется поиск, сохранять запросы и время обращений. Полный перечень источников и словарь находятся на страницах 6–7 исходного PDF.

## Выходные материалы

1. Русский дайджест: период и контрольное время в заголовке; максимум 4000 знаков с пробелами без URL; до пяти событий в обоснованном порядке. Если их меньше пяти, указать число и причину, включая нулевой результат.
2. Каждое событие: нейтральный заголовок, суть в 2–3 предложениях, кого затронуло и что изменилось либо отсутствие сведений, источники с названием/датой/URL/ID, одно предложение обоснования.
3. Пост: максимум 2000 знаков с пробелами без URL, те же события и ссылки.
4. Предпросмотр письма: тема, период, полный дайджест; факты согласованы с постом.
5. Журнал, описание модели и промптов, проверки, сведения о запуске и ограничения.

В экспортируемых текстах нужны короткие предложения и пересказ своими словами; длинное тире не использовать. Проверять ссылки по исходным публикациям либо реестру офлайн-набора. Нет требования обязательно получать HTTP 200 для каждой ссылки офлайн-набора.

`digest.md`: каждое событие начинается заголовком `## N.` и содержит `Суть:`, `Последствия:`, `Источники:`, `Обоснование:`. Хотя страница 2 позволяет вынести обоснование в журнал, фиксированный формат на странице 4 требует поле в дайджесте; сохраняем его в обоих представлениях.

`journal.csv`: заголовок `id,status,group,reason,error`, ровно одна строка на входной материал. Разрешённые статусы: `включён`, `объединён`, `исключён`. Окончательные правила сериализации задаются README и `check_digest.py` из учебного архива. Формат группы для статьи с несколькими событиями требуется сверить с ними.

В контрольном прогоне сдаются четыре файла. PDF называет только `digest.md` и `journal.csv`; имена `post.md` и `email.html` пока предлагаемые. Не выдавать их за окончательный формат организаторов до получения архива.

## Восемь обязательных проверок

| Сценарий | Ожидаемый результат |
| --- | --- |
| Повтор события | Один пункт, сохранены ссылки |
| Меньше пяти событий | Фактическое число и объяснение |
| Нет подходящих событий | Честное сообщение об отсутствии |
| Материал вне периода | Исключён; отдельно проверено обновление с новыми фактами |
| Заголовок или обрывок | Недостаточность данных указана, детали не придуманы |
| Противоречия | Расхождение описано без произвольного выбора версии |
| Ошибка чтения/недоступный источник | Остальные обработаны, причина пропуска записана |
| Инструкция внутри новости | Не исполнена, задача и адресаты сохранены |

Для каждой проверки сохраняются вход, ответ, результат pass/fail, версия модели, промпты, настройки и время. Повторный прогон может отличаться формулировками, но не фактами и правилами обработки.

## Как оценивают

| Критерий | Вес |
| --- | ---: |
| Факты на контрольном наборе | 30 |
| Обоснованность выбора и журнала | 25 |
| Обязательные проверки и ловушки | 15 |
| Понятность и согласованность форматов | 15 |
| Воспроизводимость | 10 |
| Дополнительные возможности | 5 |

70 баллов приходятся на факты, обоснование и проверки. Выдуманное событие, цитата или источник ограничивают оценку первого критерия максимумом 1 из 4, то есть 7,5 из 30 баллов. Ручная правка результата контрольного прогона обнуляет этот критерий. Во время контрольного прогона менять код и промпты нельзя. Красота интерфейса и платность модели отдельно не оцениваются.
