# Проверки notFive

Набор проверяет работающий локальный API на `127.0.0.1:8090`. Сначала запусти сервис по [инструкции](../README.md) и задай в терминале проверок тот же `NOTFIVE_API_TOKEN`. Провайдер отправляет подготовленные публикации на `/api/v1/runs` и дожидается итогового ответа. Каждый сценарий получает собственный ключ запуска, поэтому повтор дубля вызывает модель заново.

Из корня проекта выполни команду. Достаточно Node.js с поддержкой `fetch`.

```powershell
node notfive_py/evals/run.cjs
```

Для двух независимых запусков только сценария с дублем выполни `node notfive_py/evals/run.cjs --repeat-only`. В `summary.json` результат `reproducibility` оценивается отдельно. Проверка сравнивает состав и порядок событий, CVE, контрольные числа, источники и решения в журнале. Расхождения входа и конфигурации модели помечаются как блокирующие сравнение. Для оценки остальных оговорок и фактов нужна сверка с исходными статьями.

В `var/notfive-evals/` появится каталог с отдельным JSON каждого сценария, общим `summary.json` и снимком входов, промптов, схем и настроек из кода. В ответах API также сохраняются модель, которую указал Яндекс, и время запуска. В сценариях, отсеянных до обращения к модели, список вызовов пуст.

Те же проверки можно выполнить из Promptfoo.

```powershell
$config = 'notfive_py/evals/promptfooconfig.yaml'
$report = 'var/notfive-evals/' + (Get-Date -Format 'yyyyMMdd-HHmmss')
New-Item -ItemType Directory -Path $report | Out-Null
$env:PROMPTFOO_DISABLE_TELEMETRY = '1'
npx --yes promptfoo --version | Set-Content -Encoding utf8 "$report/promptfoo-version.txt"
npx --yes promptfoo validate config -c $config
Copy-Item -Path 'notfive_py/prompts.py','notfive_py/glossary.txt','notfive_py/provider.py','notfive_py/domain.py','docs/case/fixtures/real-site-cases.json' -Destination $report
npx --yes promptfoo eval -c $config --no-cache --no-share --max-concurrency 1 -o "$report/results.json"
```

Отчёты сохраняют ответы API, включая журнал, дайджест, пост и письмо. Сверь ожидаемое поведение в `real-site-cases.json` с причинами результата. Если сценарий падает, ненулевой код завершения команды ожидаем. Даты запуска хранятся отдельно от контрольного времени внутри входных данных.

Для смысловой проверки открой выпуск и исходные фрагменты рядом. Для каждого факта проверь, кто это сообщил, какова степень уверенности, сохранились ли условия, числа и единицы. У противоречивых сообщений проверь обе версии и временные оговорки. У поста сверь условия и ссылки с дайджестом. При повторе сравнивай эти данные и состав событий. Формулировки могут различаться. Проверка встроенной инструкции охватывает содержание предпросмотра. Проверку адресатов можно выполнить после подключения отправки на тестовом стенде.
