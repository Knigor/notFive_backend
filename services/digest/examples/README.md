# Запросы сбора, анализа и экспорта

[search.json](search.json) содержит тему поиска и фиксированное контрольное время `2026-11-08T13:01:59+03:00`. Это вход отдельного `POST /v1/collect`, не обучающий набор и не готовые статьи. Для полного веб-цикла используется [pipeline-web.json](pipeline-web.json) с `control_time` и массивом `sites`; поисковый запрос задан на сервере, `query` в этом файле не передаётся. Для другого периода измените `control_time`: публикации отбираются строго после T−24 часа и не позже T.

[news.json](news.json) — пример **ответа**: 12 реальных публикаций из переданного пользователем запуска с T=`2026-11-08T14:36:26+03:00`. Он повторяет структуру файла организаторов: `dataset`, `control_time`, `period_start`, `timezone`, `description`, `fields`, `items`. Это собранные исходные материалы, не учебный архив и не итоговый дайджест; смысловой отбор ещё предстоит выполнить. Значения ID, текстов, источников, URL и дат сохранены из пользовательского результата. `dataset: "web"` отличает этот набор от учебного `train`. Пример ответа относится к своему периоду и не является заранее известным результатом запроса `search.json`.

Для двух сценариев полного цикла из каталога сервиса:

```sh
# Сайты из examples/pipeline-web.json, период до текущего времени Москвы
python3 scripts/pipeline.py web --now --output-dir /tmp/notfive-web-run

# Уже готовые статьи, контрольное время из самого файла
python3 scripts/pipeline.py news /tmp/notfive-news.json --output-dir /tmp/notfive-file-run
```

`web` вызывает `POST /v1/pipeline/web`: передаёт только `control_time` и массив `sites` из 1–5 публичных доменов/HTTPS-сайтов. Фиксированный текст поиска находится в `pipelineSearchQuery` в [internal/httpapi/pipeline.go](../internal/httpapi/pipeline.go) и приведён в [README](../README.md#два-сценария-полного-цикла); поле `query` в запросе отклоняется с HTTP 400. Для фиксированного T уберите `--now`; свой JSON передайте после `web`. Сайты действуют только на этот запрос; URL раздела задаёт HTML-сбор ссылок, поиск ограничивается доменом.

`news` вызывает `POST /v1/pipeline/news`: отправляет файл как JSON-тело без парсера, нового поиска и загрузки URL. `--now` для этого сценария не применяется. По датам файла выбирается окно `(T−24h,T]`; материалы вне периода/без даты исключаются, но остаются в возвращаемом наборе и журнале. Исходный `news.json` не изменяется.

Каждый сценарий выполняет один HTTP-запрос и сохраняет `news.json`, `analysis.json` и `files/` с четырьмя файлами в новую папку. Токен читается из окружения или `.env`, таймаут CLI — 600 секунд для web и 400 секунд для news. Это реальные вызовы моделей Яндекса без автоматических повторов. Старый `/v1/pipeline` удалён и возвращает 404. [Контракт для Symfony](../README.md#два-сценария-полного-цикла).

Из папки `services/digest` можно обратиться к API напрямую:

```sh
read -r -s DIGEST_SERVICE_TOKEN
curl --fail-with-body --max-time 200 \
  http://127.0.0.1:8081/v1/collect \
  -H "Authorization: Bearer $DIGEST_SERVICE_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @examples/search.json \
  --dump-header /tmp/notfive-collect.headers \
  --output /tmp/news.json
```

При успехе API возвращает HTTP 201. В `/tmp/news.json` будет документ с массивом `items`; в заголовках — `Location` для чтения сохранённого аудита и `X-Run-ID`. curl перезаписывает указанные файлы. Описания полей и набора доступны на русском и английском через `Accept-Language`; без заголовка используется русский. Тексты статей не переводятся.

Тестовый клиент:

```sh
python3 scripts/search.py --check
python3 scripts/search.py
python3 scripts/search.py --now --output /tmp/news.json
```

`--check` проверяет настройки без запроса. `--now` подставляет текущее время Москвы в отправляемую копию, не меняя файл. Токен читается из окружения или `.env` сервиса. Обычный запуск может расходовать токены Yandex на поиск.

Клиент печатает тот же документ `news.json`, что возвращает POST. `--output` сохраняет его в новый файл с правами `0600`, не перезаписывая существующий. В `items` только принятые статьи; `missing` — массив незаполненных полей, `error` — строка или `null` (обычно `[]` и `null`). Пустой `items: []` допустим. Исключения, счётчики, предупреждения, подтверждение дат и отметки сокращения текста находятся в полном аудите `GET /v1/runs/{id}`.

Следующий этап принимает полученный `news.json` без нового поиска:

```sh
python3 scripts/analyze.py /tmp/notfive-news.json --output /tmp/notfive-analysis.json
```

Или отправьте файл в `POST /v1/analyze` с тем же Bearer-токеном. В ответе находятся `groups`, факты с `source_ids` и дословными подтверждениями, противоречия, `excluded` и `recommended_order` максимум из пяти групп. Полный аудит доступен по `Location`. Модель анализа задаётся отдельно: `YANDEX_ANALYSIS_MODEL=aliceai-llm-flash`; настройка и curl — в [инструкции анализа](../README.md#анализ-через-alice-ai-llm-flash). Если ваш выход сбора называется `/tmp/news.json`, используйте именно этот путь. Скрипт не перезаписывает существующий файл результата.

Учебный `reference.json` — эталон организаторов для проверки, он не отправляется модели и не заменяется полученным анализом. Готовый анализ не является итоговым дайджестом.

Начиная с версии сервиса 9 модель получает JSON Schema `news_analysis_v2` с `strict: true`; схема находится в [internal/analysis/schema.json](../internal/analysis/schema.json). Модель возвращает массивы групп и исключений, а API преобразует их в прежние объекты `groups` и `excluded`. Публичный формат анализа не изменён.

Для переданного `/tmp/notfive-news.json` первый реальный запуск Alice, ещё с `json_object`, завершился `incomplete/content_filter`; в том запуске готового файла анализа не было. Частичный ответ сохранён в аудите, а клиент сообщил ошибку вместо сохранения его как успешного `analysis.json`. Подробности запуска и настройка приведены в README сервиса.

Следующий запуск со строгой схемой завершился успешно: `/tmp/notfive-analysis.json`, аудит `a849e844e4c2e0b6307075b2d362da03`. Из тех же 12 статей получено 5 групп, выбраны 4 события. В результате есть 4 предупреждения: одна неподтверждённая дословная цитата и три пропущенных моделью материала. Они сохранены для разбора; успешное соответствие JSON Schema не подтверждает качество всех фактов и отбора.

Готовый анализ и исходный набор передаются в экспорт:

```sh
python3 scripts/export.py /tmp/notfive-analysis.json \
  --news /tmp/notfive-news.json \
  --output-dir /tmp/notfive-export
```

Скрипт вызывает `POST /v1/export` с `{analysis, news}` и сохраняет `digest.md`, `post.md`, `email.md`, `journal.csv` в новую папку. Она не должна существовать. Используйте новости именно того набора и периода, из которого получен анализ; пример `examples/news.json` и `/tmp/notfive-news.json` могут относиться к разным запускам. ID, ссылки и даты берутся из переданных статей, порядок событий из `recommended_order`; предупреждения не скрываются. Этот этап вызывает Alice без веб-поиска; модель задаётся `YANDEX_EXPORT_MODEL`, бюджет ответа `YANDEX_EXPORT_MAX_OUTPUT_TOKENS=8000`. Автоматической отправки письма или публикации нет. Контракт ответа с полем `files` описан в [инструкции экспорта](../README.md#формирование-четырёх-файлов).

Контракт: [README сервиса](../README.md#http-контракт-для-symfony), [OpenAPI](../openapi.json). Для веб-цикла сайты передаются в `sites`; отдельный `/v1/collect` использует `YANDEX_SEARCH_DOMAINS`; каталог источников: [SOURCES.md](../../../docs/case/SOURCES.md).
