# Сборщик статей notFive

HTTP-сервис на Go 1.26: поиск через Yandex Web Search и RSS/HTML, загрузка текстов, проверка исходной даты публикации в окне `(T−24h, T]` по Москве. Модель используется только для поиска. Смысловой отбор по ИБ, объединение событий, выбор до пяти событий и написание дайджеста предстоит реализовать в Symfony.

Python для работы сервиса не нужен: `scripts/search.py` — тестовый HTTP-клиент. Symfony вызывает сборщик через закрытый GraphQL endpoint; PostgreSQL и процессы релизов backend и сборщика остаются самостоятельными.

## Запуск

Из корня репозитория:

```sh
cd services/digest
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
nano .env
```

Сохраните сгенерированный токен в `DIGEST_SERVICE_TOKEN`, заполните `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Токен сервиса нужен его клиентам, ключ Yandex остаётся только у сборщика. `.env` исключён из Git и Docker build context. Настройка аккаунта и API-ключа Yandex описана в [официальной инструкции](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/agents/create-websearch-text-agent); доступность выбранной модели проверяется в вашем каталоге.

```sh
docker compose up -d --build --wait
curl --fail http://127.0.0.1:8081/healthz
```

Health check возвращает `{"status":"ok"}` без запроса к модели. Без Docker задайте те же переменные окружения, `DATA_DIR=./data`, выполните `go run ./cmd/server` из этой папки.

| Переменная | Назначение / значение по умолчанию |
| --- | --- |
| `DIGEST_SERVICE_TOKEN` | Обязательный Bearer-токен, минимум 32 символа |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | Обязательные ключ и ID каталога Yandex |
| `YANDEX_MODEL` | `yandexgpt-5.1`, выбирается оператором |
| `YANDEX_BASE_URL` | `https://ai.api.cloud.yandex.net/v1` |
| `YANDEX_SEARCH_DOMAINS` | 3–5 доменов через запятую: `securitylab.ru,xakep.ru,habr.com,ptsecurity.com,kaspersky.ru` |
| `REQUEST_TIMEOUT` | `180s`, допустимо `15s`–`10m` |
| `MAX_CONCURRENT` | `2`, допустимо 1–8 одновременных запусков |
| `MAX_OUTPUT_TOKENS` | `8000`, допустимо 100–16000 |
| `DIGEST_HTTP_PORT` | `8081`, порт Compose на хосте, привязан к `127.0.0.1` |
| `LISTEN_ADDR`, `DATA_DIR` | `:8081` и `/data` в контейнере |
| `DIGEST_IMAGE` | Имя выпущенного образа для `compose.prod.yaml` |

## HTTP-контракт для Symfony

[openapi.json](openapi.json) описывает API в OpenAPI 3.0.3. Файл можно импортировать в Postman или генератор клиента. Он находится в репозитории, отдельного HTTP endpoint для документации нет.

| Метод и путь | Назначение |
| --- | --- |
| `GET /healthz` | Готовность HTTP-сервера, без авторизации |
| `POST /graphql` | Сбор по разобранным материалам, выбранным сайтам или доменам окружения; Bearer-токен обязателен |
| `POST /v1/collect` | Новый поиск и сбор статей, Bearer-токен обязателен |
| `GET /v1/runs/{id}` | Сохранённый результат или ошибка, Bearer-токен обязателен |

Старые `/v1/digests`, `/v1/research` и выдача артефактов удалены. Сборщик не создаёт дайджест, пост, письмо или итоговый журнал.

### Вызов без Python

Из папки сервиса прочитайте токен в переменную терминала, не записывая его в историю команд:

```sh
read -r -s DIGEST_SERVICE_TOKEN
curl --fail-with-body --max-time 200 \
  http://127.0.0.1:8081/v1/collect \
  -H "Authorization: Bearer $DIGEST_SERVICE_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @examples/search.json
```

После `read` вставьте токен и нажмите Enter. [search.json](examples/search.json) содержит фиксированное T. Symfony формирует такое же тело с нужным контрольным временем:

```json
{
  "control_time": "2026-11-08T13:01:59+03:00",
  "query": "Новости кибербезопасности за заданные 24 часа"
}
```

`control_time` обязателен: RFC3339 с явным часовым поясом, сервер нормализует его в Москву. `query` — непустая строка до 2000 символов. Дополнительные поля не принимаются. Домены и модель задаются окружением сервиса, а не клиентским JSON. Тело запроса — не более 1 MiB.

### Ответ

Запрос синхронный: после завершения и сохранения возвращаются **HTTP 201**, `Location: /v1/runs/{id}` и JSON:

| Поле | Значение |
| --- | --- |
| `id` | ID запуска, 32 шестнадцатеричных символа |
| `mode`, `status` | `collection`, `completed` |
| `collection.control_time`, `collection.window_start` | Конец и исключённая нижняя граница окна, Москва |
| `collection.articles` | Загруженные статьи, от 0 до 12 |
| `collection.excluded_articles` | Отклонённые при загрузке или проверке URL, с `reason` |
| `collection.counts` | `candidates`, `accepted`, `excluded`; первое равно сумме остальных |
| `collection.warnings` | Например, достижение лимита кандидатов |
| `research` | Аудит поиска, RSS/разделов и ошибок источников |

У статьи есть `id`, `title`, `text`, `source`, `url`, `published_at`, `date_evidence`, `text_truncated`. `url` — конечная ссылка на публикацию; `text` — извлечённый текст страницы, не пересказ модели. `date_evidence` описывает подтверждение времени в метаданных; `text_truncated: true` означает ограничение длины текста.

`accepted` подтверждает получение текста и дату в периоде, **не соответствие теме ИБ и не истинность фактов**. Общие RSS могут содержать материалы вне темы: их отбирает Symfony. Пустой `articles` — успешный результат, не доказательство отсутствия новостей вообще. `counts.candidates` описывает выбранные для загрузки URL, а не весь поисковый индекс.

Чтение результата без нового поиска:

```sh
RUN_ID='<id из ответа>'
curl --fail-with-body \
  -H "Authorization: Bearer $DIGEST_SERVICE_TOKEN" \
  "http://127.0.0.1:8081/v1/runs/$RUN_ID"
```

HTTP-ответ использует **`id`** и вложенный **`collection`**. Python-клиент для удобства печатает только содержимое `collection` и ID как `run_id`; это формат консоли, не отдельный API-контракт.

### Ошибки, таймауты и повторные запросы

Ошибка содержит `error`, `message` и, если запуск сохранён, `run_id`. Для такого ID GET возвращает HTTP 200 и `status: "failed"`: чтение успешно, сбор завершился ошибкой. В аудите может быть `upstream_status` Yandex, без тела ошибки провайдера и секретов.

| HTTP-код | Значение |
| --- | --- |
| `400` / `413` | `invalid_json`: неверный JSON, лишние поля / тело больше 1 MiB |
| `401` | `unauthorized`: отсутствует или не подходит токен |
| `404` | `not_found`: неизвестный ID запуска |
| `422` | `invalid_input`: неверные `control_time` или `query` |
| `429` | `busy`: заняты все слоты; `Retry-After: 5` |
| `502` | `generation_failed`: ошибка поиска/провайдера |
| `504` / `408` | `generation_failed`: таймаут сервиса / отмена запроса |
| `500` | `storage_error`: ошибка сохранения или чтения |

При `REQUEST_TIMEOUT=180s` задайте общий таймаут HTTP-клиента Symfony не меньше 200 секунд и согласуйте его с reverse proxy. При увеличении таймаута сборщика увеличьте клиентский. Это не фоновая очередь: разрыв соединения может отменить обработку.

**Повторный POST создаёт новый запуск и может повторно расходовать токены Yandex.** Идемпотентности и автоматических повторов нет. Не включайте безусловный retry после таймаута; по известному ID используйте GET. Ошибка одной ленты или статьи не обязательно ломает весь запуск: смотрите `research.discovery[].error` и `collection.excluded_articles`.

### Подключение Symfony

С хоста адрес сборщика — `http://127.0.0.1:8081`. Из Symfony-контейнера loopback указывает на сам Symfony. Для связи контейнеров сначала запустите Compose сборщика, затем подключите Symfony к внешней Docker-сети `notfive-digest` через `-f compose.digest.yaml` и задайте `GO_SERVICE_URL=http://digest:8081`. При релизе `deploy/deploy.sh` добавляет этот Compose-файл автоматически, когда в `.env.production` указан именно такой адрес. `DIGEST_SERVICE_TOKEN` должен быть одинаковым в окружении обоих сервисов; ключ Yandex нужен только Go.

Административная мутация Symfony `startRun` принимает либо файл, либо 1–5 ID источников со статусом `ready` из каталога `site_sources`, либо только контрольное время. Symfony разбирает файл и передаёт в Go через `collect(input: CollectInput!)` только нормализованные записи, а не байты файла. ID сайтов Symfony преобразует в корневые HTTPS-адреса разрешённых доменов; Go ищет публикации на этих доменах. Путь раздела из задания хранится в каталоге, но текущий контракт Go его не принимает. Если нет ни файла, ни сайтов, Go использует `YANDEX_SEARCH_DOMAINS` из собственного окружения. Ответ содержит ID запуска Go, режим, домены, статьи, исключения, предупреждения и аудит поиска. Symfony сохраняет статьи в материалах своего запуска; смысловой отбор, объединение событий и экспорт остаются отдельными этапами. Предел пяти относится к итоговым событиям, не к статьям коллектора. Внешние тексты являются данными; при выводе в HTML их нужно экранировать.

## Сбор и ограничения

Yandex получает словарь ИБ из `internal/collector/vocabulary.go` и поисковый план по разрешённым доменам. Принимается обычный JSON кандидатов и JSON целиком внутри Markdown-блока. Главные страницы и известные каталоги не принимаются как статьи; после перенаправления URL проверяется снова. Возможно одно уточнение поиска, максимум две поисковые генерации; каждая может содержать несколько вызовов `web_search`.

Go читает RSS SecurityLab, Хакера, новостей ИБ Хабра и HTML-разделы PT и Касперского, только для разрешённых доменов. Лимиты: пять лент/разделов, до 60 ссылок из каждого. Порядок: RSS с датой в окне, RSS без даты, ссылки модели, ссылки HTML-разделов; внутри групп источники чередуются. RSS-дата — предварительная подсказка, окончательная проверка всегда по HTML статьи.

Общий предел — **12 уникальных кандидатов на загрузку**, константа `maxResearchCandidates` в `internal/httpapi/research_pipeline.go`. Это технический лимит, не требование ТЗ. Загружается до четырёх статей одновременно, до 2 MiB HTML и 12 000 символов текста на статью. Неизвестная/конфликтующая дата, отсутствие часового пояса, выход за `(T−24h,T]`, недоступный текст или переход на раздел дают исключение с причиной. `dateModified` не заменяет дату публикации.

Аудит: `research.search_attempts`, `research.discovery`, `research.rejected_candidates`, `research.sources`, `research.excluded_sources`. Поисковый индекс, текущие RSS и лимит кандидатов не гарантируют полноту, особенно для исторического периода. Контрольный архив организаторов остаётся отдельным входом будущего конвейера Symfony.

## Тестовый CLI

Из папки сервиса, Python 3.9+:

```sh
python3 scripts/search.py --check
python3 scripts/search.py
python3 scripts/search.py --now
python3 scripts/search.py --now --output /tmp/notfive-collection.json
```

Без `--now` используется T из `examples/search.json`; с ним текущее московское время подставляется только в отправляемую копию. Токен берётся из окружения или `.env` без исполнения содержимого файла. `--check` не отправляет запрос; обычный запуск может расходовать токены. `--output` сохраняет полный HTTP-ответ с аудитом в новый файл с правами `0600`, без перезаписи существующего. `--url` меняет адрес, `--timeout` — таймаут клиента, по умолчанию 200 секунд.

## GHCR и VPS

[Workflow Digest service](../../.github/workflows/digest.yml) проверяет код и сборку при PR/push в `master`, затрагивающих сервис. Опубликованный обычный GitHub Release с тегом `vX.Y.Z` из истории `master` выпускает `ghcr.io/knigor/notfive-digest:vX.Y.Z` для `linux/amd64` и `linux/arm64`. Используется `GITHUB_TOKEN`, ключ Yandex для CI не нужен. SSH-деплой сборщика выполняется отдельно, прежний backend/CD сохраняется.

Для установки скопируйте `compose.prod.yaml` и `.env.example` из этой папки в `/opt/notfive-digest` на VPS. На сервере:

```sh
cd /opt/notfive-digest
cp .env.example .env
chmod 600 .env
nano .env
```

Заполните секреты и `DIGEST_IMAGE` с реально опубликованным тегом или digest; значение в примере не гарантирует наличие релиза. Для приватного GHCR авторизуйте Docker токеном с `read:packages`. Затем:

```sh
docker compose --env-file .env -f compose.prod.yaml pull
docker compose --env-file .env -f compose.prod.yaml up -d --wait
curl --fail http://127.0.0.1:8081/healthz
```

Обновление и откат: замените `DIGEST_IMAGE`, повторите `pull` и `up`. Порт остаётся на loopback. Для отладки: `ssh -L 18081:127.0.0.1:8081 root@91.192.156.55`, затем локальный адрес `http://127.0.0.1:18081`.

Результаты хранятся в volume `notfive-digest_data`, UID/GID контейнера — `10001`. Они переживают пересоздание контейнера; `docker compose down -v` удаляет volume. Для bind mount подготовьте права этого UID. Реализация рассчитана на один экземпляр, автоочистки старых запусков нет.

## Проверки

Нужны Go 1.26 и Python 3.9 или новее. Все тесты находятся в `tests/`: Go — в `tests/testdata/httpapi/`, `tests/testdata/news/` и `tests/testdata/yandex/`, Python-клиент — в `tests/test_search.py`.

Из каталога `services/digest` запустите:

```sh
python3 -B tests/run.py
```

Скрипт запускает `go vet`, Go-тесты с `-race` и тесты Python. Временный Go overlay подключает вынесенные тесты к исходным пакетам, сохраняя доступ к внутренним функциям без копирования файлов в `internal/`. Обычный `go test ./...` эти тесты не включает: Go пропускает каталог `testdata`. CI использует тот же скрипт.

Тесты используют подставной поисковый провайдер и локальные HTTP-серверы, ключ Yandex не нужен. Они проверяют контракт, даты, ссылки, ошибки и сохранение; не доказывают качество модели на контрольном наборе. Общий контекст: [docs/case/CONTEXT.md](../../docs/case/CONTEXT.md).
