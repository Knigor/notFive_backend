# Сбор, анализ и экспорт notFive

HTTP-сервис на Go 1.26: поиск через Yandex Web Search и RSS/HTML, загрузка текстов, проверка исходной даты публикации в окне `(T−24h, T]` по Москве. Отдельный этап анализа передаёт готовые статьи Alice AI LLM Flash без веб-поиска и возвращает группы событий, факты, противоречия, исключения и до пяти выбранных событий. Этап экспорта принимает анализ вместе с исходными статьями и формирует `digest.md`, `post.md`, `email.md` и `journal.csv`. Тексты пишет Alice; формат файлов, ссылки и журнал собирает Go.

Python для работы сервиса не нужен: `scripts/pipeline.py web` и `scripts/pipeline.py news` запускают выбранный сценарий одним HTTP-запросом; `scripts/search.py`, `scripts/analyze.py` и `scripts/export.py` проверяют этапы отдельно. Symfony уже вызывает сбор через закрытый GraphQL endpoint `POST /graphql`. REST-анализ, экспорт и полный цикл пока не подключены к `startRun`; примеры ниже предназначены для следующего этапа интеграции. PostgreSQL и процессы релизов backend и Go остаются самостоятельными.

## Запуск

Из корня репозитория:

```sh
cd services/digest
cp .env.example .env
chmod 600 .env
openssl rand -hex 32
nano .env
```

Сохраните сгенерированный токен в `DIGEST_SERVICE_TOKEN`, заполните `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Токен сервиса нужен его клиентам, ключ Yandex остаётся только у сборщика. `.env` исключён из Git и Docker build context. Настройка аккаунта и API-ключа Yandex описана в [официальной инструкции](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/agents/create-websearch-text-agent); доступность выбранной модели проверяется в вашем каталоге.

```sh
docker compose up -d --build --wait
curl --fail http://127.0.0.1:8081/healthz
```

Health check возвращает `{"status":"ok"}` без запроса к модели. Без Docker задайте те же переменные окружения, `DATA_DIR=./data`, выполните `go run ./cmd/server` из этой папки.

| Переменная | Назначение / значение по умолчанию |
| --- | --- |
| `DIGEST_SERVICE_TOKEN` | Обязательный Bearer-токен, минимум 32 символа |
| `YANDEX_API_KEY`, `YANDEX_FOLDER_ID` | Обязательные ключ и ID каталога Yandex |
| `YANDEX_MODEL` | `yandexgpt-5.1`, выбирается оператором |
| `YANDEX_ANALYSIS_MODEL` | `aliceai-llm-flash`, отдельная модель анализа готовых статей |
| `YANDEX_ANALYSIS_MAX_OUTPUT_TOKENS` | `12000`, бюджет ответа анализа; допустимо 100–16000 |
| `YANDEX_EXPORT_MODEL` | Модель экспорта; при отсутствии используется `YANDEX_ANALYSIS_MODEL`, обычно `aliceai-llm-flash` |
| `YANDEX_EXPORT_MAX_OUTPUT_TOKENS` | `8000`, бюджет ответа экспорта; допустимо 100–16000 |
| `YANDEX_BASE_URL` | `https://ai.api.cloud.yandex.net/v1` |
| `YANDEX_SEARCH_DOMAINS` | 1–5 доменов для отдельной ручки `/v1/collect`; веб-сценарий получает свои сайты в `sites` запроса |
| `REQUEST_TIMEOUT` | `180s`, допустимо `15s`–`10m` |
| `MAX_CONCURRENT` | `2`, допустимо 1–8 одновременных запусков |
| `MAX_OUTPUT_TOKENS` | `8000`, допустимо 100–16000 |
| `DIGEST_HTTP_PORT` | `8081`, порт Compose на хосте, привязан к `127.0.0.1` |
| `LISTEN_ADDR`, `DATA_DIR` | `:8081` и `/data` в контейнере |
| `DIGEST_IMAGE` | Имя выпущенного образа для `compose.prod.yaml` |

## HTTP-контракт для Symfony

[openapi.json](openapi.json) описывает REST API в OpenAPI 3.0.3. GraphQL-контракт находится в [graph/schema.graphqls](graph/schema.graphqls). Файл можно импортировать в Postman или генератор клиента. Он находится в репозитории, отдельного HTTP endpoint для документации нет.

| Метод и путь | Назначение |
| --- | --- |
| `GET /healthz` | Готовность HTTP-сервера, без авторизации |
| `POST /graphql` | Сбор по разобранным материалам, выбранным сайтам или доменам окружения; Bearer-токен обязателен |
| `POST /v1/pipeline/web` | Сбор с переданных сайтов, анализ и четыре файла одним запросом |
| `POST /v1/pipeline/news` | Отбор из переданного `news.json`, анализ и четыре файла без парсера |
| `POST /v1/collect` | Новый поиск и сбор статей, Bearer-токен обязателен |
| `POST /v1/analyze` | Анализ готового `news.json` без поиска, Bearer-токен обязателен |
| `POST /v1/export` | Четыре файла из анализа и исходных статей, Bearer-токен обязателен |
| `GET /v1/runs/{id}` | Сохранённый результат или ошибка, Bearer-токен обязателен |

Старые `/v1/digests`, `/v1/research`, `/v1/pipeline` и маршруты скачивания артефактов удалены; старый `/v1/pipeline` возвращает 404. Новый `/v1/export` возвращает содержимое четырёх файлов в JSON.

### Два сценария полного цикла

Оба запроса защищены `Authorization: Bearer <DIGEST_SERVICE_TOKEN>` и синхронно возвращают новости, анализ и четыре файла. Отдельные `/v1/collect`, `/v1/analyze`, `/v1/export` остаются доступны для проверки этапов. Старый `/v1/pipeline` заменён двумя маршрутами и возвращает 404.

**Сайты: `POST /v1/pipeline/web`.** Передайте обязательные `control_time` и массив `sites`:

```json
{
  "control_time": "2026-11-08T13:01:59+03:00",
  "sites": [
    "https://www.securitylab.ru",
    "https://xakep.ru",
    "https://habr.com/ru/hubs/infosecurity/"
  ]
}
```

`sites` содержит от 1 до 5 публичных доменов или HTTPS-адресов сайтов/разделов. Строка вместо массива не принимается. Повторы доменов, IP-адреса, локальные имена, учётные данные в URL и неподдерживаемые порты отклоняются. Из сайтов формируется `allowed_domains` только для этого запроса; окружение, общие настройки и другие параллельные запуски не меняются. Для известных главных страниц используются имеющиеся RSS, переданный раздел используется как HTML-источник ссылок. Для остальных сайтов читается указанная HTML-страница. Поисковый инструмент ограничивает поиск доменом, поэтому переданный путь раздела не гарантирует, что все найденные публикации будут находиться только внутри него. Загрузка статей по-прежнему проверяет публичный HTTPS-адрес, домен, перенаправления и исходную дату публикации.

T обязательно содержит часовой пояс. Сервер отбирает публикации строго в `(T−24h, T]` по Москве, затем анализирует и формирует файлы. Текущие часы вместо T сервер не подставляет. Модели и ключи задаются окружением Go-сервиса.

Поисковый запрос фиксирован на сервере в константе `pipelineSearchQuery`: [internal/httpapi/pipeline.go](internal/httpapi/pipeline.go). Symfony не передаёт `query`; это поле в теле `/v1/pipeline/web` отклоняется с HTTP 400 как неизвестное. Точный текст:

```text
Найди свежие новости кибербезопасности за заданные 24 часа, важные для российских организаций: новые уязвимости, инциденты, утечки и защитные меры. Не включай прогнозы, годовые отчёты и вечнозелёные обзоры. Укажи даты, источники, последствия и оговорки. Если подходящих публикаций нет, прямо сообщи об этом и ничего не выдумывай.
```

Это запрос этапа поиска. Промпты последующего анализа и экспорта, а также файловый сценарий `/v1/pipeline/news` не изменены. Отдельный `/v1/collect` по-прежнему принимает свой `query`.

**Готовый файл: `POST /v1/pipeline/news`.** Отправьте содержимое `news.json` целиком в теле `application/json`, без обёртки `news`, без `sites` и без multipart. Используется тот же формат организаторов, что для `/v1/analyze`: `dataset`, `control_time`, `items` и остальные поля `news.json`.

Сервис не ищет новые статьи, не читает RSS/HTML и не загружает URL из файла. Из переданного набора он допускает к анализу только статьи с текстом и подтверждённой датой в `(T−24h, T]`. Если `period_start` задан, он должен совпадать с T−24 часами. Статьи вне периода, без даты или с ошибкой получения исключаются с причиной. Все исходные `items` сохраняются в возвращаемом `news` и журнале, поэтому журнал учитывает каждый входной материал. Время набора нормализуется в Москву; содержимое статей не исправляется. `dataset` может быть `web`, `train` или другим именем; лимита в 12 статей для файла нет, но остаются пределы 1 MiB тела и 120 000 символов в текстах допущенных статей. Для файла нельзя использовать `--now`: контрольное время берётся из самого JSON.

Команды из каталога сервиса:

```sh
# Сайты из examples/pipeline-web.json, T = текущее московское время
python3 scripts/pipeline.py web --now --output-dir /tmp/notfive-web-run

# Готовый файл и его контрольное время, без поиска
python3 scripts/pipeline.py news /tmp/notfive-news.json --output-dir /tmp/notfive-file-run
```

Для веб-сценария можно передать свой JSON после `web`; без `--now` используется T из него. Каждый запуск делает один HTTP-запрос. Скрипт сохраняет результат в новую папку; существующая папка не перезаписывается:

```text
notfive-web-run/
  news.json
  analysis.json
  files/
    digest.md
    post.md
    email.md
    journal.csv
```

CLI читает токен из окружения или `.env`. `--timeout` по умолчанию 600 секунд для web и 400 секунд для news; запуск расходует токены Яндекса. `--check` проверяет вход и локальные настройки без вызова API.

Те же запросы через curl:

```sh
read -r -s DIGEST_SERVICE_TOKEN
curl --fail-with-body --max-time 600 \
  http://127.0.0.1:8081/v1/pipeline/web \
  -H "Authorization: Bearer $DIGEST_SERVICE_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @examples/pipeline-web.json \
  --output /tmp/notfive-web-response.json

curl --fail-with-body --max-time 400 \
  http://127.0.0.1:8081/v1/pipeline/news \
  -H "Authorization: Bearer $DIGEST_SERVICE_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/notfive-news.json \
  --output /tmp/notfive-file-response.json
```

Обе ручки отвечают HTTP 201 с одной структурой (многоточия обозначают содержимое объектов):

```json
{
  "run_id": "<ID запуска>",
  "status": "completed",
  "news": {"...": "новости из сбора или входного файла"},
  "analysis": {"...": "analysis.json"},
  "files": {
    "digest.md": "...",
    "post.md": "...",
    "email.md": "...",
    "journal.csv": "..."
  },
  "warnings": []
}
```

`warnings` объединяет замечания этапов без повторяющихся строк. При пустом допущенном наборе анализ и экспорт не вызывают модель, но возвращают четыре файла с нулевым результатом и журнал исключений. Прозу пишет модель; `Accept-Language` локализует служебные сообщения, но не переводит статьи и русский выпуск.

Один запрос занимает один слот `MAX_CONCURRENT`. Каждый этап ограничен `REQUEST_TIMEOUT`: для веб-сценария общий предел — `3 × REQUEST_TIMEOUT` (540 секунд по умолчанию), для файла — `2 × REQUEST_TIMEOUT` (360 секунд). Клиенту подходят 600 и 400 секунд соответственно; допустимо использовать 600 секунд для обоих. Согласуйте таймауты reverse proxy/PHP. Отмена запроса останавливает дальнейшие этапы. Автоматических повторов и идемпотентности нет: повторный POST запускает обработку заново.

Один аудит `GET /v1/runs/{run_id}` имеет `mode: pipeline` и `pipeline.source: web|news`. У веб-запуска есть `research` и `collection`, у файлового их нет; `analysis` и `export` сохраняются по мере выполнения. Блок `pipeline` хранит `version: pipeline-v2`, текущий `stage`, промпты фактически используемых этапов, исходные новости и успешный `result`. Настройки сайтов, моделей и таймаутов фиксируются в аудите. `X-Run-ID` и `Location` указывают на сохранённый запуск. При сбое следующие этапы не выполняются; ответ содержит `error`, `message`, `run_id` и `stage`, уже полученные данные остаются в аудите.

Возможны 400/413 для некорректного JSON/размера, 422 для входа или сайтов, 401 для токена, 429 для занятых слотов, 503 для недоступной конфигурации, 502 для ошибки провайдера/модели, 504 для таймаута, 408 для отмены. Ошибка сохранения возвращает 500 и не подтверждает сохранение новых данных.

Пример Symfony с `HttpClientInterface`; адрес и токен передаются конфигурацией:

```php
// Сценарий с сайтами.
$response = $httpClient->request('POST', rtrim($digestBaseUrl, '/').'/v1/pipeline/web', [
    'auth_bearer' => $digestServiceToken,
    'headers' => ['Accept-Language' => 'ru'],
    'json' => [
        'control_time' => $controlTime->format(DATE_RFC3339),
        'sites' => $sites,
    ],
    'timeout' => 600,
    'max_duration' => 600,
]);
```

Для уже загруженного и проверенного файла отправьте его JSON как тело второго запроса:

```php
$response = $httpClient->request('POST', rtrim($digestBaseUrl, '/').'/v1/pipeline/news', [
    'auth_bearer' => $digestServiceToken,
    'headers' => ['Accept-Language' => 'ru', 'Content-Type' => 'application/json'],
    'body' => $newsJson,
    'timeout' => 400,
    'max_duration' => 400,
]);

$status = $response->getStatusCode();
$result = $response->toArray(false);
if ($status !== 201) {
    // Сохранить run_id/stage и показать message; GET читает аудит без повторной генерации.
    return $result;
}
$files = $result['files'];
$analysis = $result['analysis'];
$warnings = $result['warnings'];
```

Вместо `body` с JSON-строкой можно передать разобранный документ в опции `json`. Для Symfony на том же хосте адрес — `http://127.0.0.1:8081`. Из PHP-контейнера `http://digest:8081` доступен только в общей Docker-сети; `127.0.0.1` указывает на сам PHP-контейнер. Это примеры подключения REST-полного цикла: текущий `GoRunDispatcher` использует только GraphQL-сбор. Настройка общей сети описана ниже. API формирует файлы и не публикует их или отправляет письма.

Собрано 12 статей, выбраны 5 групп, созданы четыре файла и 12 строк журнала. Дайджест — 3199 знаков, пост — 1459 без URL/разметки. Результаты сохранены в `var/exports/notfive-pipeline-2026-11-08/` в корне backend и совпадают с аудитом. Остались 10 предупреждений: лимит кандидатов, пропуски анализа и неподтверждённая цитата группы G4; готовность текста к публикации требует отдельного просмотра. Пройден Go vet, целевые race-тесты полного цикла и сбора, проверка CLI на один запрос/сохранение, Docker build/health и HTTP 400/401/422 на RU/EN. В этой проверке выполнен один полный цикл: одна поисковая генерация, один анализ и один экспорт.

### Вызов без Python

Из папки сервиса прочитайте токен в переменную терминала, не записывая его в историю команд:

```sh
read -r -s DIGEST_SERVICE_TOKEN
curl --fail-with-body --max-time 200 \
  http://127.0.0.1:8081/v1/collect \
  -H "Authorization: Bearer $DIGEST_SERVICE_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @examples/search.json \
  --dump-header /tmp/notfive-collect.headers \
  --output /tmp/news.json
```

После `read` вставьте токен и нажмите Enter. [search.json](examples/search.json) содержит фиксированное T. Для отдельного REST-сбора клиент формирует такое тело с нужным контрольным временем:

```json
{
  "control_time": "2026-11-08T13:01:59+03:00",
  "query": "Новости кибербезопасности за заданные 24 часа"
}
```

`control_time` обязателен: RFC3339 с явным часовым поясом, сервер нормализует его в Москву. `query` — непустая строка до 2000 символов. Дополнительные поля не принимаются. Домены и модель задаются окружением сервиса, а не клиентским JSON. Тело запроса — не более 1 MiB.

### Ответ

Запрос синхронный: после завершения и сохранения возвращаются **HTTP 201** и документ в формате `news.json` организаторов. [Пример ответа](examples/news.json) содержит 12 реальных публикаций из переданного пользователем запуска; это исходные материалы для следующего этапа, не готовый дайджест.

Корень JSON содержит ровно семь полей:

| Поле | Значение |
| --- | --- |
| `dataset` | `web`: набор публикаций из открытых источников |
| `control_time` | Конец окна T в московском времени |
| `period_start` | Исключённая нижняя граница T−24 часа |
| `timezone` | `Europe/Moscow` |
| `description` | Описание набора |
| `fields` | Описания восьми полей материала |
| `items` | Загруженные статьи с подтверждённой датой в окне, от 0 до 12 |

Каждый элемент `items` содержит ровно `id`, `title`, `text`, `source`, `url`, `published_at`, `missing`, `error`. Исходные ID, заголовки, тексты, источники, URL и даты сохраняются. `url` — конечная ссылка на публикацию, `text` — извлечённый текст страницы, не пересказ модели. `missing` всегда массив, `error` — строка или `null`; формат также допускает `null` для `text` и `published_at`. В обычном успешном сборе у принятой статьи `missing: []`, `error: null`: материалы без текста или подтверждённой даты исключаются до экспорта.

В `description` и значениях `fields` язык выбирается по `Accept-Language`: `ru` или `en`, по умолчанию `ru`. Заголовок `Content-Language` сообщает выбранный язык метаданных. Сами статьи остаются на языке источника и не выдаются за перевод.

Пустой `items: []` — успешный результат, не доказательство отсутствия новостей вообще. Приём статьи подтверждает получение текста и дату в периоде, **не соответствие теме ИБ и не истинность фактов**. Общие RSS могут содержать материалы вне темы: смысловой отбор выполняется отдельным запросом `/v1/analyze`.

### Сохранённый аудит

В заголовках успешного POST возвращаются `X-Run-ID` (32 шестнадцатеричных символа) и `Location: /v1/runs/{id}`. В примере curl выше заголовки сохраняются в `/tmp/notfive-collect.headers`, документ — в `/tmp/news.json`. Эти имена можно заменить; curl перезаписывает указанные файлы.

Чтобы прочитать аудит без нового поиска, скопируйте значение `X-Run-ID`:

```sh
RUN_ID='<значение X-Run-ID>'
curl --fail-with-body \
  -H "Authorization: Bearer $DIGEST_SERVICE_TOKEN" \
  "http://127.0.0.1:8081/v1/runs/$RUN_ID"
```

GET сохраняет прежний формат полного запуска: `id`, `mode`, `status`, `collection`, `research` и сведения о вызове провайдера. В `collection` находятся исходные `articles`, `excluded_articles` с причинами, `counts` и `warnings`. `counts.candidates` описывает выбранные для загрузки URL, а не весь поисковый индекс; оно равно сумме `accepted` и `excluded`. В статьях аудита сохранены `date_evidence` и `text_truncated`; `text_truncated: true` означает ограничение длины извлечённого текста. Эти технические поля не добавляются в `items` нового документа.

Python-клиент печатает тот же документ `news.json`, который возвращает POST, без отдельной обёртки `run_id` или `collection`. Его `--output` сохраняет этот документ; аудит по-прежнему читается через GET.

### Ошибки, таймауты и повторные запросы

Ошибка содержит `error`, `message` и, если запуск сохранён, `run_id`. Для такого ID GET возвращает HTTP 200 и `status: "failed"`: чтение успешно, сбор завершился ошибкой. В аудите может быть `upstream_status` Yandex, без тела ошибки провайдера и секретов.

| HTTP-код | Значение |
| --- | --- |
| `400` / `413` | `invalid_json`: неверный JSON, лишние поля / тело больше 1 MiB |
| `401` | `unauthorized`: отсутствует или не подходит токен |
| `404` | `not_found`: неизвестный ID запуска |
| `422` | `invalid_input`: некорректный вход выбранного этапа: период, ID, запрос, несовместимые анализ и новости |
| `429` | `busy`: заняты все слоты; `Retry-After: 5` |
| `502` | `generation_failed`: ошибка поиска/провайдера |
| `504` / `408` | `generation_failed`: таймаут сервиса / отмена запроса |
| `500` | `storage_error`: ошибка сохранения или чтения |

При `REQUEST_TIMEOUT=180s` задайте общий таймаут HTTP-клиента Symfony не меньше 200 секунд и согласуйте его с reverse proxy. При увеличении таймаута сборщика увеличьте клиентский. Это не фоновая очередь: разрыв соединения может отменить обработку.

**Повторный POST создаёт новый запуск и может повторно расходовать токены Yandex.** Идемпотентности и автоматических повторов нет. Не включайте безусловный retry после таймаута; по известному ID используйте GET. Ошибка одной ленты или статьи не обязательно ломает весь запуск: смотрите `research.discovery[].error` и `collection.excluded_articles` в сохранённом аудите через GET.

### Подключение Symfony

С хоста адрес сборщика — `http://127.0.0.1:8081`. Из Symfony-контейнера loopback указывает на сам Symfony. Для связи контейнеров сначала запустите Compose сборщика, затем подключите Symfony к внешней Docker-сети `notfive-digest` через `-f compose.digest.yaml` и задайте `GO_SERVICE_URL=http://digest:8081`. При релизе `deploy/deploy.sh` добавляет этот Compose-файл автоматически, когда в `.env.production` указан именно такой адрес. `DIGEST_SERVICE_TOKEN` должен быть одинаковым в окружении обоих сервисов; ключ Yandex нужен только Go.

Административная мутация Symfony `startRun` принимает либо файл, либо 1–5 ID источников со статусом `ready` из каталога `site_sources`, либо только контрольное время. Symfony разбирает файл и передаёт в Go через `collect(input: CollectInput!)` только нормализованные записи, а не байты файла. ID сайтов Symfony преобразует в корневые HTTPS-адреса разрешённых доменов; Go ищет публикации на этих доменах. Путь раздела из задания хранится в каталоге, но текущий GraphQL-контракт его не принимает. Если нет ни файла, ни сайтов, Go использует `YANDEX_SEARCH_DOMAINS` из собственного окружения. Ответ содержит ID запуска Go, режим, домены, статьи, исключения, предупреждения и аудит поиска. Symfony сохраняет статьи в материалах своего запуска; смысловой отбор, объединение событий и экспорт остаются отдельными этапами. Предел пяти относится к итоговым событиям, не к статьям коллектора. Внешние тексты являются данными; при выводе в HTML их нужно экранировать.

Токен хранится на сервере Symfony, не передаётся браузеру. Для подключения остальных этапов Symfony может получить `news.json` от `/v1/collect`, передать его в `/v1/analyze`, затем отправить оба документа в `/v1/export` либо вызвать одну из двух `/v1/pipeline/*`. Текущий `GoRunDispatcher` этого не делает: он использует только GraphQL-сбор. Полученные строки `files` можно сохранить, показать пользователю и передать в отдельный механизм доставки Symfony. Go не отправляет письма и не публикует посты. ID каждого запуска доступен в `X-Run-ID`, аудит — по `Location`. Предел пяти относится к выбранным событиям, не к статьям коллектора или всем найденным группам. Внешние тексты являются данными; при выводе в HTML их нужно экранировать.

## Анализ через Alice AI LLM Flash

### Настройка

1. В каталоге Yandex Cloud сервисному аккаунту нужна роль [`ai.languageModels.user`](https://aistudio.yandex.ru/ru/docs/ai-studio/security/). API-ключ должен иметь область `yc.ai.languageModels.execute`; [создание ключа в AI Studio](https://aistudio.yandex.ru/ru/docs/ai-studio/operations/get-api-key) задаёт нужные разрешения. Используйте секретную часть ключа, а не его ID. Если существующий ключ имеет эти права, новый не нужен.
2. В `services/digest/.env` оставьте существующие `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`, `YANDEX_BASE_URL` и `DIGEST_SERVICE_TOKEN`. Добавьте:

   ```dotenv
   YANDEX_ANALYSIS_MODEL=aliceai-llm-flash
   YANDEX_ANALYSIS_MAX_OUTPUT_TOKENS=12000
   ```

   Сервис сам составляет URI `gpt://<YANDEX_FOLDER_ID>/aliceai-llm-flash`. [Модель](https://aistudio.yandex.ru/ru/docs/ai-studio/concepts/generation/models) имеет контекст 65 536 токенов. `YANDEX_MODEL` относится к поиску: менять его для анализа не требуется.
3. Из каталога сервиса примените настройки:

   ```sh
   docker compose up -d --build --wait digest
   python3 scripts/analyze.py /tmp/notfive-news.json --output /tmp/notfive-analysis.json
   ```

Клиент читает сервисный токен из окружения или `.env`, вызывает API, печатает анализ и сохраняет его в новый файл с правами `0600`. Если файл уже существует, выберите другое имя. Исходный `news.json` не изменяется. Этот вызов может расходовать токены модели; автоматических повторов и переключения на другую модель нет.

Без Python отправьте тот же файл в API:

```sh
read -r -s DIGEST_SERVICE_TOKEN
curl --fail-with-body --max-time 200 \
  http://127.0.0.1:8081/v1/analyze \
  -H "Authorization: Bearer $DIGEST_SERVICE_TOKEN" \
  -H 'Content-Type: application/json' \
  --data-binary @/tmp/notfive-news.json \
  --dump-header /tmp/notfive-analyze.headers \
  --output /tmp/notfive-analysis.json
```

После `read` вставьте токен и нажмите Enter. curl перезаписывает указанный файл. При успехе возвращаются HTTP 201, `X-Run-ID` и `Location: /v1/runs/{id}`; тело — сам анализ, без обёртки запуска.

### Вход и результат

Вход — документ `news.json` с обязательными `dataset`, `control_time`, `items`; у каждого материала нужен уникальный непустой `id`. Если указан `period_start`, он должен совпадать с T−24 часа; время нормализуется в `Europe/Moscow`. Размер тела — до 1 MiB, суммарная длина текстов допущенных статей — до 120 000 символов Unicode (это технический предел, не точный подсчёт токенов). Отдельного ограничения в 12 статей у анализа нет: можно передать учебный набор из 30 материалов. Метаданные `description` и `fields` принимаются, но не становятся инструкциями модели. До запроса код исключает материалы с ошибкой загрузки, пустым текстом, неизвестной датой или датой вне `(T−24h,T]`. Если подходящих материалов нет, возвращается пустой анализ с причинами исключения без вызова модели.

| Поле ответа | Содержимое |
| --- | --- |
| `dataset`, `control_time`, `period_start`, `timezone` | Метаданные входа, нормализованные кодом |
| `groups` | Объект с ключами групп, например `G1`; каждая содержит `name`, `ids`, `facts`, `contradictions`, `selection_reason` |
| `facts` внутри группы | `statement`, исходные `source_ids` и `evidence`: пары `article_id` / дословная `quote` |
| `contradictions` внутри группы | Расхождения с `description` и `source_ids`, без произвольного выбора версии |
| `recommended_order` | До пяти ID выбранных групп в порядке важности |
| `excluded` | Объект «ID материала → причина исключения» |
| `warnings` | Замечания к ответу модели и проверкам ссылок/цитат |

Групп может быть больше пяти, одна статья может относиться к нескольким событиям. Анализ пишется по-русски; `Accept-Language: ru/en` выбирает язык служебных сообщений, но не переводит исходные статьи или факты. Проверки намеренно мягкие: сомнительные цитаты, ссылки и пропущенные решения сообщаются через `warnings`. Результат модели не становится подтверждённым эталоном только из-за валидного JSON.

Используется Responses API с `text.format = {"type":"json_schema","name":"news_analysis_v2","strict":true,"schema":...}`, температурой `0.1` и `store=false`, без `tools` и `web_search`. Схема хранится в [internal/analysis/schema.json](internal/analysis/schema.json), промпт — `news-analysis-v2-json-schema`, версия сервиса — 12. Схема задаёт структуру ответа, но не доказывает правильность фактов.

В ответе самой модели `groups` — массив групп с полем `id`, а `excluded` — массив объектов `article_id` / `reason`. Код преобразует эти массивы в прежние публичные объекты `groups` и `excluded`, не редактируя содержание фактов. Контракт `/v1/analyze` и формат сохраняемого клиентом `analysis.json` остаются прежними. `train/reference.json` остаётся эталоном организаторов: он не отправляется модели и не перезаписывается. Поля `must_include` и другие критерии эталона не выдаются за автоматически установленные требования.

`GET /v1/runs/{id}` сохраняет полный вход, инструкции, настройки, `mode: analysis` и `analysis` с `prompt_version`, `model_input`, `generation` (ответ, usage, trace), `result` при успехе и необязательным `failure_reason` при отказе/незавершённом ответе. Ошибки используют общие HTTP-коды сервиса; дополнительно `503 analysis_unavailable` означает, что провайдер анализа не настроен. Сохранённый аудит не требует повторного вызова модели.

Первый реальный запуск 8 ноября на `/tmp/notfive-news.json` (12 статей, около 63 тысяч символов), ещё в режиме `json_object`, получил от Яндекса HTTP 200, но `status: incomplete` с причиной `content_filter`. Аудит: `427619a2f5b7e16604f828257d1da9a3`; usage — 14 057 входящих и 623 исходящих токена. В том запуске готовый `analysis.json` не был сформирован: частичный ответ остался только в аудите, API сообщил ошибку. Это не ошибка ключа или ID каталога; конкретную причину срабатывания фильтра Яндекс не раскрыл. Также отдельно сообщаются `max_output_tokens` и `refusal`, без автоматического повторения запроса или смены модели.

Повторный запуск с JSON Schema (`a849e844e4c2e0b6307075b2d362da03`) завершён успешно за 31,7 секунды; результат сохранён в `/tmp/notfive-analysis.json`. Входные 12 статей не менялись, исходный ответ модели соответствует переданной схеме, преобразование в публичный формат сохранило факты и цитаты. Получено 5 групп, выбраны 4 (`G1`–`G4`), в `excluded` — 7 материалов: 4 исключила модель, ещё 3 она пропустила и код отметил их явно. Требуют просмотра 4 предупреждения: одна цитата группы `G3` не подтверждена дословно и три материала остались без решения модели. Usage: 14 144 входящих, 2 670 исходящих, всего 16 814 токенов. Это успешный технический прогон; качество отбора и всех фактов на контрольном наборе ещё не проверено.

## Формирование четырёх файлов

`POST /v1/export` принимает два связанных документа. `analysis` задаёт группы и порядок выбранных событий; `news` содержит исходные тексты, URL, источники и даты. Одного `analysis.json` недостаточно для восстановления достоверных ссылок и полного журнала. Передавайте новости именно того набора и периода, из которого получен анализ.

```json
{
  "analysis": {"...": "полный объект из /v1/analyze"},
  "news": {"...": "исходный news.json"}
}
```

Это схематичный пример; `...` не является допустимым полем запроса. Для реального запуска из каталога сервиса:

```sh
docker compose up -d --build --wait digest
python3 scripts/export.py /tmp/notfive-analysis.json \
  --news /tmp/notfive-news.json \
  --output-dir /tmp/notfive-export
```

Скрипт читает токен из окружения или `.env` сервиса, отправляет JSON в `/v1/export` и сохраняет четыре файла UTF-8 в новую папку. Он не меняет входные документы и не перезаписывает существующую папку. Для повторного запуска выберите другое имя выходной папки. Python нужен только для этой проверки; при подключении экспорта Symfony сможет вызвать HTTP API напрямую.

Успешный ответ HTTP 201:

```json
{
  "files": {
    "digest.md": "# Дайджест по кибербезопасности...\n",
    "post.md": "# Новости кибербезопасности...\n",
    "email.md": "Тема: Дайджест по кибербезопасности...\n",
    "journal.csv": "id;status;group;reason;error\n..."
  },
  "warnings": []
}
```

Здесь показана структура ответа, а не фактические тексты выпуска. `X-Run-ID` и `Location` позволяют прочитать сохранённый аудит: `mode: export`, `export.prompt_version`, `export.model_input`, `export.generation` с ответом и usage, `export.result` с теми же файлами либо `export.failure_reason`. Для повторного скачивания используйте аудит, без нового POST и расхода токенов.

- Alice получает подготовленный анализ без `web_search`; ответ ограничен JSON Schema, промпт `news-export-v2-json-schema`. Для групп без обнаруженных проблем к нему добавляются исходные статьи. Если обнаружены ошибки источников или дословных подтверждений, во входе генерации остаются имя и ID группы, а `facts`, `contradictions` и `selection_reason` очищаются; тексты её статей не подаются для генерации этого события. Это не замена ID и не исправление исходного анализа: оба входных документа полностью сохраняются в аудите. Alice сама формулирует описание нерешённой проблемы источника.
- Всю содержательную прозу дайджеста и поста пишет Alice. Код применяет формат файлов, сохраняет порядок `recommended_order` и подставляет URL, даты, ID и названия источников из `news`.
- `digest.md` содержит период, контрольное время, до пяти событий с полями `Суть`, `Последствия`, `Источники`, `Обоснование`. `post.md` описывает те же события в том же порядке; `email.md` включает полный текст этого дайджеста.
- `journal.csv` собирается кодом: разделитель `;`, колонки `id;status;group;reason;error`, одна строка на каждый элемент `news.items`. Статусы: `включён`, `объединён`, `исключён`.
- Предупреждения анализа сохраняются. Код не переписывает полученный текст событий и не исправляет несвязанные источники подстановкой других ID. Описания полей JSON Schema задают модели бюджеты длины; текст не обрезается кодом. Замечания к длине и содержанию возвращаются в `warnings` и не блокируют выдачу. Если ответ модели не содержит обязательной прозы или нарушает структуру, API сообщает ошибку: ручных заготовок вместо текста Alice и автоматической смены модели нет. JSON Schema проверяет структуру, но не гарантирует качество текста.
- При пустом `recommended_order` четыре файла формируются без вызова модели. Русские артефакты являются содержимым выпуска; `Accept-Language: en` меняет служебные сообщения, а не переводит выпуск.

Используются те же ключ и каталог Yandex, что для анализа. Настройки в `.env` сервиса:

```dotenv
YANDEX_EXPORT_MODEL=aliceai-llm-flash
YANDEX_EXPORT_MAX_OUTPUT_TOKENS=8000
```

Если `YANDEX_EXPORT_MODEL` отсутствует, сервер использует модель анализа. Поиск и анализ сохраняют свои отдельные настройки. Автоматической отправки файлов в Symfony, публикации и рассылки на этом этапе нет.

Проверка 8 ноября на `/tmp/notfive-analysis.json` и `/tmp/notfive-news.json`: запуск `94fef880c658c57c7367723ee2917222` завершён за 12,6 секунды. ## Сбор и ограничения

Yandex получает словарь ИБ из `internal/collector/vocabulary.go` и поисковый план по разрешённым доменам. Принимается обычный JSON кандидатов и JSON целиком внутри Markdown-блока. Главные страницы и известные каталоги не принимаются как статьи; после перенаправления URL проверяется снова. Возможно одно уточнение поиска, максимум две поисковые генерации; каждая может содержать несколько вызовов `web_search`.

Go читает RSS SecurityLab, Хакера, новостей ИБ Хабра и HTML-разделы PT и Касперского, только для разрешённых доменов. Лимиты: пять лент/разделов, до 60 ссылок из каждого. Порядок: RSS с датой в окне, RSS без даты, ссылки модели, ссылки HTML-разделов; внутри групп источники чередуются. RSS-дата — предварительная подсказка, окончательная проверка всегда по HTML статьи.

Общий предел — **12 уникальных кандидатов на загрузку**, константа `maxResearchCandidates` в `internal/httpapi/research_pipeline.go`. Это технический лимит, не требование ТЗ. Загружается до четырёх статей одновременно, до 2 MiB HTML и 12 000 символов текста на статью. Неизвестная/конфликтующая дата, отсутствие часового пояса, выход за `(T−24h,T]`, недоступный текст или переход на раздел дают исключение с причиной. `dateModified` не заменяет дату публикации.

Аудит: `research.search_attempts`, `research.discovery`, `research.rejected_candidates`, `research.sources`, `research.excluded_sources`. Поисковый индекс, текущие RSS и лимит кандидатов не гарантируют полноту, особенно для исторического периода. Контрольный архив организаторов остаётся отдельным входом: Symfony принимает JSON/CSV, а REST-сценарий `/v1/pipeline/news` — готовый `news.json`.

## Тестовый CLI

Из папки сервиса, Python 3.9+:

```sh
python3 scripts/search.py --check
python3 scripts/search.py
python3 scripts/search.py --now
python3 scripts/search.py --now --output /tmp/news.json
```

Без `--now` используется T из `examples/search.json`; с ним текущее московское время подставляется только в отправляемую копию. Токен берётся из окружения или `.env` без исполнения содержимого файла. `--check` не отправляет запрос; обычный запуск может расходовать токены. `--output` сохраняет тот же документ `news.json`, что выводится в консоль, в новый файл с правами `0600`, без перезаписи существующего. Аудит в этот файл не входит. `--url` меняет адрес, `--timeout` — таймаут клиента, по умолчанию 200 секунд.

## GHCR и VPS

[Workflow Digest service](../../.github/workflows/digest.yml) проверяет код и сборку при PR/push в `master`, затрагивающих сервис. Опубликованный обычный GitHub Release с тегом `vX.Y.Z` из истории `master` выпускает `ghcr.io/knigor/notfive-digest:vX.Y.Z` для `linux/amd64` и `linux/arm64`. Используется `GITHUB_TOKEN`, ключ Yandex для CI не нужен. SSH-деплой сборщика выполняется отдельно, прежний backend/CD сохраняется.

Для установки скопируйте `compose.prod.yaml` и `.env.example` из этой папки в `/opt/notfive-digest` на VPS. На сервере:

```sh
cd /opt/notfive-digest
cp .env.example .env
chmod 600 .env
nano .env
```

Заполните секреты и `DIGEST_IMAGE` с реально опубликованным тегом или digest; значение в примере не гарантирует наличие релиза. Для приватного GHCR авторизуйте Docker токеном с `read:packages`. Затем:

```sh
docker compose --env-file .env -f compose.prod.yaml pull
docker compose --env-file .env -f compose.prod.yaml up -d --wait
curl --fail http://127.0.0.1:8081/healthz
```

Обновление и откат: замените `DIGEST_IMAGE`, повторите `pull` и `up`. Порт остаётся на loopback. Для отладки: `ssh -L 18081:127.0.0.1:8081 root@91.192.156.55`, затем локальный адрес `http://127.0.0.1:18081`.

Результаты хранятся в volume `notfive-digest_data`, UID/GID контейнера — `10001`. Они переживают пересоздание контейнера; `docker compose down -v` удаляет volume. Для bind mount подготовьте права этого UID. Реализация рассчитана на один экземпляр, автоочистки старых запусков нет.

## Проверки

Нужны Go 1.26 и Python 3.9 или новее. Все тесты находятся в `tests/`: Go — в `tests/testdata/httpapi/`, `tests/testdata/news/` и `tests/testdata/yandex/`, Python-клиент — в `tests/test_search.py`.

Из каталога `services/digest` запустите:

```sh
python3 -B tests/run.py
```

Скрипт запускает `go vet`, Go-тесты с `-race` и тесты Python. Временный Go overlay подключает вынесенные тесты к исходным пакетам, сохраняя доступ к внутренним функциям без копирования файлов в `internal/`. Обычный `go test ./...` эти тесты не включает: Go пропускает каталог `testdata`. CI использует тот же скрипт.

Тесты используют подставной поисковый провайдер и локальные HTTP-серверы, ключ Yandex не нужен. Они проверяют контракт, даты, ссылки, ошибки и сохранение; не доказывают качество модели на контрольном наборе. Общий контекст: [docs/case/CONTEXT.md](../../docs/case/CONTEXT.md).
