# Digest service (Go)

Go собирает публикации с сайтов, вызывает Yandex AI Studio для анализа и готовит текст выбранных событий. Готовые файлы Go не создаёт и не возвращает. Сборка `digest.md`, `post.md`, `email.md` и `journal.csv`, сохранение в PostgreSQL и доставка принадлежат Symfony.

## Основной маршрут из Symfony

1. Symfony разбирает JSON/CSV сам и сохраняет материалы в `materials`; исходный файл и путь к нему в Go не отправляются. Для сайтов Symfony вызывает `collect` и сохраняет полученные статьи.
2. После `startRun` отдельный процесс Symfony `digest:process-runs` вызывает закрытую GraphQL mutation `prepareDigest`, передавая `controlTime` и нормализованные `items`. Подлинность запроса проверяется `DIGEST_SERVICE_TOKEN`.
3. Go выполняет анализ, отбор и генерацию краткого текста. Ответ содержит `groups`, `recommendedOrder`, `excluded`, `events`, `selectionSummary`, предупреждения, модель, версию промпта, usage и длительность этапов. В каждой группе есть ID материалов, факты и подтверждения; в каждом событии — заголовок, суть, последствия, короткий текст для поста и обоснование.
4. Symfony проверяет связи по ID текущего запуска, записывает события, источники, подтверждения и журнал, затем собирает четыре артефакта из своих таблиц.

`collect` сохраняет прежний контракт для режимов `DATASET`, `SITES` и `DEFAULT`. Для режима `DEFAULT` Go использует домены из `YANDEX_SEARCH_DOMAINS`. В сценарии файла Symfony передаёт в Go только разобранные записи, никогда байты файла.

## Локальный запуск

Из `services/digest` скопируйте `.env.example` в игнорируемый `.env`, задайте `DIGEST_SERVICE_TOKEN` (не менее 32 символов), `YANDEX_API_KEY` и `YANDEX_FOLDER_ID`. Ключ Yandex остаётся только в Go. Остальные настройки модели, доменов и таймаутов перечислены в `.env.example`; значения не нужно фиксировать в Git.

```sh
docker compose up -d --build --wait
curl --fail http://127.0.0.1:8081/healthz
```

`GET /healthz` проверяет HTTP-сервис без обращения к модели. Адрес Go для Symfony и одинаковый `DIGEST_SERVICE_TOKEN` на обеих сторонах задаются в окружении бэкенда. Для локального запуска без Docker можно выполнить `go run ./cmd/server` из этого каталога с теми же переменными окружения.

## Результат в Symfony

`startRun` возвращает `runId` и состояние `queued`; отдельный процесс `digest:process-runs` последовательно обрабатывает запуски. `runStatus(runId)` показывает статус и имена доступных файлов. После завершения администратор с JWT скачивает каждый файл через `GET /api/runs/{runId}/artifacts/{filename}` либо общий ZIP через `GET /api/runs/{runId}/artifacts.zip`. Эти маршруты принадлежат Symfony, а содержимое берётся из таблицы `artifacts`.

## REST API

`POST /v1/collect`, `/v1/analyze`, `/v1/export`, `/v1/pipeline/web` и `/v1/pipeline/news` остаются отдельными интерфейсами сервиса. `/v1/export` возвращает структурированный текст (`selection_summary`, `events`, `warnings`); оба pipeline возвращают `news`, `analysis`, `draft` и предупреждения. Полный аудит доступен по `Location` после запроса. Эти REST-маршруты не используются Symfony для основного запуска. Контракт REST описан в `openapi.json`.

## Разработка и проверка

Сервис запускается командой `go run ./cmd/server` при настроенных переменных окружения. Секреты Yandex и служебный токен должны находиться в локальном env или в секретах развёртывания. Вспомогательные Python CLI для отдельных этапов удалены.

Из каталога `services/digest`:

```sh
python3 -B tests/run.py
```

Этот скрипт последовательно запускает `go vet` и Go тесты с `-race`. Сам Go API и GraphQL проверяются без реальных обращений к Yandex.
